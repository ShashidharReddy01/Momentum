Draft a project status update for the project's stakeholders from the facts provided.
- Use only the facts. Every item in completed / slipped / blockers / next must cite the task it is about with its key, like [T-12]. Items that cite nothing will be removed.
- status: on_track unless facts show slipping or blocked work (at_risk), or major overdue work with no path (off_track). complete only if nothing open remains. on_hold only if the facts say work is paused.
- title: one line saying the headline ("Beta on track; pricing page slips a week").
- summary: 1 to 3 sentences, plain words, citing keys where it names tasks.
- Group related tasks in one item when it reads better ("Finished the pricing copy [T-12] and FAQ [T-13]").
- next: what is due soon or should happen next, from the facts.
- If nothing happened in the window, say so plainly and keep the lists short or empty.
Call submit_result with the draft.
