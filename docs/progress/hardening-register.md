# Hardening register (Phase 7)

Every finding from the Phase 7 audit (E7.0) and the Phase 6.5 exit (UX8), one row each. **Policy (product owner, 2026-10-04): every finding is fixed, P3 included**; the AI triages and records decisions here.

Severity: **P0** broken, data loss, security or permission leak · **P1** wrong, confusing, or a crash on reachable input · **P2** polish · **P3** nice-to-have.
Status: open → fixed (commit) · each fix ships with the test that proves it.

How findings are found:
- **Robustness sweep** (`apps/api/tests/test_api_robustness.py`): every API operation with boundary values (NUL, emoji/RTL, 10k characters; `PROBE_FULL=1` adds wrong types and extreme numbers); any 5xx is a finding.
- **UI audit** (`tools/ux/audit.mjs` on `tools/ux/serve.sh`): every screen at 5 viewports × 2 themes: page overflow, clipped / covered / unnamed controls, axe WCAG 2.2 AA serious+critical, console errors; screenshots reviewed by eye.
- **Edge-case review** per feature (the matrix in `phase-7.md` E7.0), **live AI runs** against the real gateway, and the **150-user load test**.

## Reviewed, no change needed

- **Design detector at UX8** (`impeccable detect` on the 34 UI files changed since Phase 6.5): the project tabs' active underline (`border-b-2` on a tab with a rounded hover) and the left rule on quotes in rich text (`blockquote`). Both are the standard pattern for those elements, not card accents.
- **Semgrep** (`p/python`, `p/react`, `p/typescript`, `p/secrets`): two `text()` calls in `migrations/env.py` build `CREATE SCHEMA` / `SET search_path` from `MOMENTUM_DB_SCHEMA`, which settings restrict to `^[a-z_][a-z0-9_]{0,62}$`. Not user input.
- **Dependency audits** (2026-10-05): `pip-audit` on the locked runtime requirements and `pnpm audit` found no known vulnerabilities.
- **Keyboard pass, section actions**: the "Actions for section …" buttons fade in on focus; the first pass measured them mid-fade. The tool now re-measures after 250 ms.

- **Concurrent field edits** (two people change the same task at once): edits send only the changed field, so different fields never clobber each other; the same field is last-write-wins and everyone sees the result live (Asana behaves the same). The description, the one long-form field, already detects conflicts and offers Keep mine / Use theirs / Copy.
- **Configuration edits without undo** (E7.0 undo audit): creating or editing a custom field definition, a rule (incl. enabling / disabling) or a form, and creating a template, record activity but aren't undoable: they're changed back the same way they were made. What hides data or can't be redone by hand (archive, remove, delete) is undoable (H53–H56). API tokens (security), invitations and Asana import runs stay one-way by design.
- **Deleted and archived parents** (`test_deleted_parents.py`, kept as a regression test): everything that hangs off a deleted task, parent task or section answers 404 (comment, tag, depend, edit, follow, multi-home, reschedule, convert, attachments, feed, subtasks); a deleted blocker drops out of its dependents' lists; restoring a parent brings its subtasks back. An **archived project stays editable** (tasks, sections), as in Asana: archiving files a project away, it doesn't freeze it. A **disabled person** can't be assigned, followed in or added to a project and drops out of @mention search; re-enabling someone makes them invited again (S7.5.4).
- **Recurrence and daylight saving**: occurrences are pure dates, so DST changes can't move them.
