Building a real job-queue-safe way to hand a short-lived secret to a worker (an ephemeral cache, or a callback pattern) is infrastructure this codebase doesn't have, and disproportionate to build for this slice. The import instead **runs synchronously inside the API request** — the PAT lives only in that request's `AsanaClient` instance, never durable anywhere, in exchange for no progress streaming and no resume-from-partial-failure (a failure rolls back the whole `uow.transaction()`, `ImportJob` row included — nothing partial persists to resume from or clean up).

- **S2.7.2 CSV import (done, no reduced scope — a much smaller spec than Asana's):** new `domain/tasks/csv_import.py` + `csv_import_router.py`. No migration needed — this reuses the existing `tasks`/`sections` tables directly. Two endpoints: `POST /projects/{id}/import/csv/preview` (headers + first 10 sample rows + total row count, from a plain multipart file upload) and `POST /projects/{id}/import/csv` (the file plus a JSON-encoded `mapping` `Form` field naming which CSV column maps to which of title/section/assignee-email/due-date/completed).
  - **Deliberately the opposite architectural choice from the Asana importer, disclosed in the module's own docstring:** the Asana importer does raw ORM construction row-by-row because it's reconciling a foreign system's own identity model (external ids, idempotency links) against Momentum's; a CSV upload has none of that — it's a trusted in-app action by someone who already has editor access to the project. So `import_csv()` calls the exact same `create_task`/`set_completed` functions the rest of the app uses (`domain/tasks/service.py`), row by row, rather than bypassing them. A referenced section name that doesn't exist yet is created via the existing `create_section`; an unmapped or blank column is simply skipped for that row.
  - **A real permission-bypass bug found by the test written to catch it, not assumed away:** the first version wrapped each row's `create_task()` call in `except DomainError`, and `Forbidden`/`NotFound` are `DomainError` subclasses — so a non-member's entire import would come back **HTTP 200** with `created=0, skipped=<every row>`, its per-row errors quietly listing "access denied" as if it were a data problem, instead of surfacing a real 403/404. `test_non_member_cannot_import` failed immediately (`assert 200 in (403, 404)`), which is what caught it. Fixed two ways: (1) an explicit `get_visible_project` + `require_project_role(role, "editor", ...)` check runs once, before the row loop, so a caller without access never gets to iterate rows at all; (2) the per-row `except` was narrowed from `DomainError` to `ValidationFailed` — only a genuine bad-row problem (e.g. `create_task` rejecting the row) is caught and turned into a per-row error; a permission error now always propagates as a real HTTP error, never disguised as "0 imported."

## Phase retros
### Phase 1 (2026-09-23)
**Exit criteria:** all met. E2E J1, J3 and J2 (up to inbox delivery, which is Phase 2) pass with `make e2e`, plus a quick-add journey; the 2,000-task list renders in 0.44s and scrolls at 60fps (`docs/engineering/performance.md`); `tests/test_permission_matrix.py` covers 7 kinds of user x 9 task actions, and teams/projects/sections have their own matrices; `make check`: 158 backend and 124 web tests.

- **Went well:**
  - Checking every slice in a real browser against the production build caught what unit tests with mocks couldn't: rapid-create ordering, phantom autosaves, a double-follow insert on self-assigned quick adds, a quick-add project default race, and unreadable list rows on phones.
  - The generic undo registry with its coverage test kept "every mutation is undoable" true as features grew.
  - Syncing on read (My Tasks placements) avoided a background job and its failure modes.
- **Went less well:**
  - Mocked UI tests passed while the real app was wrong (single-project fixtures hid the default-project bug). New rule: fixtures should have at least two of whatever the code chooses between.
  - Two backend tests computed "today" in UTC instead of the user's timezone and failed late in the UTC day. Tests that depend on dates must use the actor's timezone.
  - The full parallel web suite needed more time for async queries (`asyncUtilTimeout` 4s). Flakes are fixed at the root, never retried away.
- **Watch in Phase 2:**
  - The initial JS bundle is 222 KB gzipped (Phase 0: 178 KB). Split Tiptap and dnd-kit out of the entry chunk before Board and Calendar add more.
  - Home and My Tasks resolve subtask ancestors one query per subtask. Fine at 10-15 users; batch it if profiles show it.
  - Realtime (Phase 2) should replace the refetch-on-focus and invalidate-on-close paths (Home, the pane).
- **Needs product-owner decision:** an assignee who isn't a project member can edit, move (between the project's sections) and delete that one task. All of these are undoable and documented in auth §6. Say if deleting should require project membership instead.
